# PRD.md — 제품 요구사항

TeamUp 서비스 기능 명세. "무엇을 만드는가"를 정의한다. 기술 구현은 ARCHITECTURE.md 참고.

---

## 1. 서비스 개요

### 한 줄 정의
아이디어는 있지만 만들 사람이 없는 사람과, 만들 수 있지만 뭘 할지 모르는 사람을 이어주는 사이드프로젝트 팀원 매칭 플랫폼.

### 핵심 차별점
기존 서비스(HOLA 등)가 개발자 위주인 것과 달리, **비개발자도 기획자로 참여**할 수 있는 문을 연다. 아이디어 제공자를 "기획자로 동행하는 사람"으로 대우하고, 구조와 보상으로 참여를 떠받친다.

### 타겟 사용자
- **아이디어 제공자(기획자)**: 개발은 못 하지만 문제의식·아이디어가 있는 사람. 비개발자 포함.
- **실행자(개발자/디자이너)**: 만들 실력은 있지만 아이디어나 팀을 찾는 사람.

## 2. 서비스 구조 — 두 개의 층

### 가벼운 층: 커뮤니티
- 말머리 태그 게시판(아이디어/질문/기타). 부담 없이 아이디어를 던지는 곳.
- 방치돼도 "지나간 글"일 뿐 — 죽은 프로젝트가 안 됨.
- 아이디어의 인큐베이터 역할.

### 무거운 층: 정식 모집
- 실행 의지가 확정된 글만. 개발자 모집 / 기획자 모집.
- 완성도 있는 폼, 지원·매칭.

### 다리: 승격
- 커뮤니티 [아이디어] 글이 반응 좋으면 → "정식 모집으로 만들기" → 팀 결성으로 이어짐.
- 공간은 분리하되 흐름은 연결.

## 3. 핵심 기능

### 3.1 커뮤니티
- **목록**: 말머리 태그 필터(전체/아이디어/질문/기타), 최신순, 페이지네이션.
- **상세**: 글 본문 + 댓글. 아이디어 글이면 "정식 모집으로 만들기" 승격 버튼.
- **작성**: 말머리 선택 + 제목 + 본문. 심플.

### 3.2 정식 모집
- **목록**: 유형 필터(전체/개발자/기획자), 카드에 완성도·역할·지원자수.
- **상세**: 완성도 게이지 + 구조화 기획 정보 + 역할 + 지원 버튼.
- **작성 ★핵심**: 아래 3.3 참고.

### 3.3 모집 작성 — 기획자 3종 장치 (서비스의 심장)
비개발자 기획자가 "던지고 끝"이 되지 않도록 떠받치는 3가지:

1. **기획자 역할 가이드 카드**: "아이디어만 던지고 끝이 아닙니다. 문서화·의사결정·QA로 함께해주세요. 그럼 기획 포트폴리오가 남습니다." (기대치 정렬 + 동기부여)
2. **구조화 폼**: 전문용어 대신 일상어 질문으로 유도.
   - 어떤 문제를 겪었나요?
   - 누가 어떤 상황에 쓰나요?
   - 꼭 필요한 기능 3가지는?
   - 비슷한 앱/사이트 링크
   - → 답하면 저절로 기획 문서가 됨.
3. **기획 완성도 게이지**: 폼 채운 정도로 % 표시. **강제 아님, 보상**. 더 채울수록 완성도 오르고 목록에서 신뢰도로 보여 개발자가 더 붙음.

### 3.4 지원 / 매칭
- 모집 상세에서 "지원하기" → 지원 메시지 + 상태(대기/수락/거절).
- 같은 사람이 같은 모집에 중복 지원 불가.
- 작성자는 대시보드에서 지원자 확인.

### 3.5 인증
- 이메일/비밀번호 + 소셜(구글/카카오). Supabase Auth.

### 3.6 대시보드
- 내 프로필 요약.
- 탭: 내 모집 / 내 글 / 지원한 모집(상태 표시).

## 4. 사용자 플로우

### 플로우 A — 비개발자 기획자
1. 회원가입 → 2. 커뮤니티에 아이디어 글 (부담 없이) → 3. 반응 좋으면 "정식 모집으로 만들기" → 4. 구조화 폼 채우며 기획 완성도 올림 → 5. 개발자 지원 받음 → 6. 팀 결성

### 플로우 B — 개발자
1. 회원가입 → 2. 모집 목록에서 관심 프로젝트 탐색(완성도 높은 것 신뢰) → 3. 상세 확인 → 4. 지원하기 → 5. 수락되면 팀 합류

### 플로우 C — 가벼운 참여
1. 커뮤니티에서 아이디어/질문 구경 → 2. 댓글로 의견 → 3. 관심 생기면 회원가입/모집 참여

## 5. MVP 범위

### 포함 (Phase 1)
- 커뮤니티 (목록/상세/작성 + 댓글 + 승격)
- 정식 모집 (목록/상세/작성 + 기획자 3종 장치)
- 지원/매칭
- 인증 (이메일 + 소셜)
- 대시보드
- 빈/로딩/에러 상태 + 폼 검증

### 제외 (Phase 2 이후)
- AI 기능 (아이디어→기획서 정리, 의미 기반 매칭)
- RN 모바일 앱 + Spring 백엔드 전환
- 좋아요/북마크
- 글 수정 페이지
- 브레인스토밍 스터디, 알림, 팀 협업 툴

## 7. 성공 기준 (MVP)

- 비개발자가 아이디어를 구조화 폼으로 등록할 수 있다.
- 개발자가 완성도 높은 모집을 찾아 지원할 수 있다.
- 커뮤니티 글이 정식 모집으로 승격되는 흐름이 동작한다.
- 로그인/지원/작성이 매끄럽게 되고, 빈/에러 상황도 안내된다.
- Vercel에 배포되어 실제 접속 가능.
