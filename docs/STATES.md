# STATES.md — 상태 & 폼 검증 (모바일)

모든 데이터 화면은 정상 상태만 만들지 말 것. 빈/로딩/에러를 반드시 처리. 폼은 검증 필수. 문구는 웹과 동일하게 유지하고, 구현만 RN(React Query + RHF).

---

## 1. 목록·상세 3가지 상태 (React Query)

모든 목록(모집/대시보드)·상세에 필수:

- **빈 상태**: 안내 문구 + 다음 행동 유도 버튼 (그냥 "데이터 없음" 금지)
- **로딩**: 스켈레톤 (스피너보다 스켈레톤 선호). `isLoading`.
- **에러**: 안내 + "다시 시도" 버튼. `isError` + `refetch()`.

```
const { data, isLoading, isError, refetch } = useQuery(...)
if (isLoading) return <RecruitListSkeleton />
if (isError)  return <ErrorState onRetry={refetch} />
if (!data?.length) return <EmptyState message="..." actionLabel="..." />
```

당겨서 새로고침(pull-to-refresh)으로 `refetch` 연결 권장.

| 화면 | 메시지 | 액션 |
|------|--------|------|
| 모집 목록 | 아직 모집이 없어요. 첫 모집을 등록해보세요. | 모집 등록 |

## 3. 폼 검증 규칙 (react-hook-form + zod)

에러 표시: 입력 필드 테두리 빨강 + 아래 빨간 메시지. 제출 시 전체 + 블러 시 해당 필드. **타이핑 중엔 에러 안 띄움**(`mode: 'onBlur'` + 제출 시 재검증).

| 폼 | 필드 | 규칙 | 에러 메시지 |
|----|------|------|-------------|
| 로그인 | 이메일 | 필수·형식 | 올바른 이메일 형식이 아니에요 |
| 로그인 | 비밀번호 | 필수 | 비밀번호를 입력해주세요 |
| 회원가입 | 이메일 | 필수·형식·중복(서버) | 이미 가입된 이메일이에요 |
| 회원가입 | 닉네임 | 필수·2~20자 | 닉네임은 2자 이상이에요 |
| 회원가입 | 비밀번호 | 필수·8자 이상 | 8자 이상 입력해주세요 |
| 모집 작성 | 유형 | 필수 선택 | 유형을 선택해주세요 |
| 모집 작성 | 제목 | 필수·5~60자 | 제목을 입력해주세요 |
| 모집 작성 | 설명 | 필수·10자 이상 | 설명을 조금 더 작성해주세요 |
| 모집 작성 | 역할 | 최소 1개 | 최소 1개의 역할이 필요해요 |
| 지원 | 메시지 | 선택·최대 1000자 | (선택) |

## 4. 검증 구현

- **라이브러리**: react-hook-form + `@hookform/resolvers/zod`.
- **스키마 공유**: zod 스키마는 `src/schema/`(웹 `features/*/schema.ts`에서 복붙). 웹 API와 같은 스키마 → 검증 일관성.
- **이중 검증**: 클라이언트(즉시 피드백) + 웹 API 서버 검증(신뢰). 서버가 최종.
- **타이밍**: `mode: 'onBlur'`, 제출 시 전체 재검증. 타이핑 중엔 에러 숨김.
- **표시**: `Controller`로 필드 감싸고 `fieldState.error`로 테두리·메시지.
- **서버 에러**: API 응답 `{ error, fieldErrors }`를 받아 `setError`로 해당 필드에 매핑, 또는 토스트.
- **제출 중**: 버튼 비활성 + 로딩 인디케이터(`isSubmitting` / mutation `isPending`).
- **중복 지원**: `POST /api/applications` 400 응답 시 "이미 지원한 모집이에요" 안내.
