# 2차 알파테스트 체크리스트 — 배포된 웹 API + 모바일 앱

> 작성일: 2026-08-24. 대상: 최근 세션에서 바뀐 부분들(웹 REST API 신설·`alreadyApplied`·`revalidateTag` 버그 수정, RN 앱 스캐폴딩) 전체를 실사용 관점에서 점검.
> 자동으로 확인 가능한 건(curl/tsc/lint) 아래 "0. 자동 점검 결과"에 이미 돌려봤고, **여기서부터는 실제로 손으로 눌러봐야 확인되는 것들.**

## 0. 자동 점검 결과 (이미 확인 완료)

| 항목 | 결과 |
|---|---|
| 웹 페이지(`/`, `/recruit`, `/community`, `/login`, `/signup`) | 200 |
| `GET /api/recruit`, `GET /api/recruit/[id]` | 200, `alreadyApplied` 포함 |
| `POST /api/applications`·`/api/recruit`·`/api/profile`, `GET /api/dashboard` (미인증) | 401 |
| `GET /api/recruit/[없는id]` | 404 |
| `/dashboard`, `/recruit/new` (미인증) | 307 → `/login` 리다이렉트 |
| `/api-doc`, `/api/openapi.json` (프로덕션) | 404 (의도대로 비공개) |
| 전역 404(`/zzz`) | 404, 커스텀 안내 페이지 |
| `TeamUp`·`TeamUp-mobile` 둘 다 `tsc --noEmit` | 통과 |

### 🟡 자동 점검 중 발견한 것 (버그일 가능성, 판단 필요)

- **`/recruit/[없는id]`·`/community/[없는id]`가 커스텀 404 UI는 정상 렌더하는데 HTTP 상태 코드는 200으로 나감** — 원인 규명 완료, **Next.js 자체의 알려진 버그**로 확인되어 **손대지 않기로 결정** (판단 근거는 `TeamUp/docs/DEVLOG.md` 2026-08-24 항목 참고).
- **Supabase pooler 연결이 몇 초 정도 일시적으로 끊기는 현상**이 이번 세션 검증 중 2번 관찰됨(로컬·프로덕션 API가 순간적으로 500). `pg_stat_activity`로 직접 확인해보니 DB 자체는 건강하고(연결 수 적음, 고갈 아님) 몇 초 후 재시도하면 바로 복구됨. 코드 문제는 아닌 것 같은데 **재현 빈도가 늘면 원인 파볼 필요**.

## 1. 모바일 앱 — 이번에 고친 버그 재검증 (최우선)

- [ ] **지원 완료 상태 유지**: 모집 하나에 지원 → 상세 화면 나갔다가 다시 들어가도 "지원 완료"로 보이는지. 앱 강제 종료(`force-stop`) 후 재실행해도 유지되는지.
- [ ] **지원 성공 시 에러 메시지 안 뜨는지**: 지원하기 눌렀을 때 "지원 처리 중 오류가 발생했습니다" 같은 문구 없이 바로 "지원 완료"로 바뀌는지 (이전엔 성공해도 500으로 보였음).
- [ ] **중복 지원 시 메시지**: 이미 지원한 모집에 다시 지원 시도(버튼이 막혀있으면 API를 직접 두 번 호출하거나, 다른 계정으로 지원 후 같은 계정으로 재시도 등으로 우회) → "이미 지원한 모집입니다"로 명확히 뜨는지.
- [ ] **1차 리포트의 미해결 버그 2**: 간헐적으로 "지원 처리 중 오류가 발생했습니다"가 뜨는데 실제론 성공하는 현상 — 몇 번 더 재현 시도. (원인 후보였던 "캐시 무효화 실패로 인한 500"은 이번에 고쳤으니, 그래도 재현되면 원인이 다른 데 있다는 뜻 — `src/lib/api-client.ts`의 `res.json()` 파싱 실패 쪽 의심.)

## 2. 모바일 앱 — 핵심 여정 풀 플로우 (실기기 권장, 에뮬레이터 아님)

지난 1차 테스트는 헤드리스 에뮬레이터라 ANR이 반복됐었음(리포트 1장 참고) — **가능하면 실제 안드로이드 기기**로 아래를 처음부터 끝까지.

- [ ] 앱 설치 → 스플래시 화면(#FFF4E3 배경) → 깜빡임 없이 다음 화면
- [ ] 세션 없는 상태로 첫 실행 → 로그인 화면
- [ ] **회원가입**: 새 계정으로 가입 → 검증 에러(짧은 비밀번호, 잘못된 이메일 형식, 이미 가입된 이메일) 각각 확인 → 성공 시 목록 화면 진입
- [ ] **로그인**: 잘못된 비밀번호 → 에러 메시지, 정상 로그인 → 목록 화면
- [ ] **로그아웃 → 재로그인** 없이 앱 재실행 시 세션 유지되는지 (반대로 로그아웃 후엔 확실히 로그인 화면으로 가는지)
- [ ] **모집 목록**: 기술스택 필터 칩 토글, pull-to-refresh, 필터 조건에 안 맞는 조합으로 빈 상태 문구 확인
- [ ] **오프라인 상태**(기내 모드)에서 목록 진입 → 에러 상태 + "다시 시도" 버튼 동작
- [ ] **모집 상세**: 완성도 게이지·기술스택·역할 목록 표시, 웹에서 보던 것과 값 일치하는지
- [ ] **마이페이지**: 지원한 모집 목록에 방금 지원한 게 바로 반영되는지, 상태 라벨(대기중/수락/거절) 정확한지

## 3. 크로스체크 — 웹 ↔ 모바일 데이터 일관성

- [ ] 모바일에서 지원 → **웹**(`team-up-olive.vercel.app`)에 같은 계정으로 로그인해서 마이페이지에 반영되는지
- [ ] **웹**에서 모집 작성자 계정으로 로그인 → 지원자 관리 화면(`/recruit/[id]/applicants`)에서 모바일발 지원이 보이는지 → 수락/거절 → 모바일 마이페이지에 상태 반영되는지
- [ ] 웹에서 새 모집 하나 등록 → 모바일 목록에 즉시(새로고침 시) 뜨는지

## 4. 배포 환경 자체 점검

- [ ] **EAS internal 빌드**(dev-client 아닌 진짜 배포 프로필)로 APK 뽑아서 설치 — Metro 개발 서버 없이도 정상 동작하는지 (지금까지 테스트는 dev-client라 로컬 Metro에 의존했을 가능성)
- [ ] `eas.json`에 `development`/`internal`/`production` 세 프로필이 있는데, 각 프로필로 빌드했을 때 API_BASE_URL이 의도대로 프로덕션(`team-up-olive.vercel.app`)을 가리키는지 확인 (`.env`/`app.json`의 `extra` 설정 재확인)
- [ ] Expo 웹 프리뷰(`npx expo start --web`)는 CORS 미처리 상태라 API 호출이 막힘 — **알려진 제약**이니 굳이 테스트할 필요는 없음(원하면 별도로 CORS 처리 요청).

## 5. 우선순위 낮음 (여유 있으면)

- [ ] 소셜 로그인(구글/카카오)까지 모바일에서 되는지 — 지금 RN 쪽엔 이메일 로그인만 구현돼있어서 해당 없으면 스킵
- [ ] 다크모드 기기에서 실행 시 색 깨짐 없는지 (`app.json`이 `userInterfaceStyle: "light"`로 고정돼있어 원래 다크모드 안 타야 정상 — 확인 차)
- [ ] 화면 회전(가로 모드) — 우선순위 낮음, `orientation: "portrait"` 고정이라 기본적으로 안 돌아가는 게 정상
